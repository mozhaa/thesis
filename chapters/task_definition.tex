\section{Постановка задачи} \label{task_definition}

Проведённый обзор существующих решений показал, что универсальные системы сжатия с произвольным доступом либо не поддерживают операции записи (вставки и удаления), либо требуют полной переупаковки значительной части данных. Узкоспециализированные форматы привязаны к конкретной структуре данных и не позволяют эффективно модифицировать содержимое. Таким образом, актуальной является разработка библиотеки, объединяющей прозрачное сжатие с полноценной произвольной записью и чтением.

\textbf{Целью работы} является создание библиотеки \texttt{Compio}, удовлетворяющей следующим ключевым требованиям:
\begin{itemize}
    \item интерфейс, аналогичный стандартной библиотеке ввода/вывода (\texttt{open/close/read/write/seek/tell});
    \item эффективный произвольный доступ к сжатым данным, включая операции вставки и удаления;
    \item возможность подключения произвольных алгоритмов сжатия;
    \item поддержка нескольких логических файлов в одном файле-контейнере.
\end{itemize}

Для достижения этой цели в рамках работы необходимо решить следующие \textbf{задачи}:

\begin{enumerate}
    \item \textbf{Разработать формат файла-контейнера и архитектуру библиотеки.}
    Формат должен обеспечивать хранение метаданных, индекса и сжатых блоков в одном файле, быть самодостаточным для переноса между системами и поддерживать динамическое выделение места под разнородные структуры (аллокатор блоков внутри файла).

    \item \textbf{Реализовать блочное сжатие с управлением внутренней фрагментацией.}
    Данные логического файла разбиваются на блоки переменного размера, сжимаемые независимо. Для предотвращения деградации производительности при длительных последовательностях вставок и удалений необходимо ввести механизмы слияния и разделения блоков для борьбы с внутренней фрагментацией.

    \item \textbf{Построить систему индексации на основе B-дерева.}
    Для отображения позиций логических файлов на физические адреса сжатых блоков требуется реализовать B-дерево, оптимизированное для работы с дисковой памятью. Дерево должно поддерживать не только точечные операции, но и эффективные массовые сдвиги ключей с использованием отложенных операций, что критично для вставки и удаления.

    \item \textbf{Реализовать кэширование узлов индекса и распакованных блоков.}
    Для минимизации дисковых операций и вызовов компрессора необходимо разработать два независимых кэша: для узлов B-дерева и для данных в распакованном виде. Кэш блоков должен сохранять согласованность при массовых сдвигах, возникающих при вставке/удалении.

    \item \textbf{Предоставить API на языке C с поддержкой подключаемых алгоритмов сжатия.}
    Пользовательский интерфейс должен быть представлен в виде набора функций на C, использующих непрозрачные дескрипторы. Должна быть предусмотрена возможность задания собственных функций компрессии/декомпрессии, а также сохранения типа алгоритма в заголовке контейнера для восстановления при открытии.

    \item \textbf{Провести экспериментальное исследование.}
    Требуется измерить эффективность предложенных методов борьбы с внутренней фрагментацией и сравнить производительность \texttt{Compio} с аналогами (\texttt{seekable zstd}, \texttt{zran}) в сценариях произвольного чтения, а также оценить влияние размера блока на trade-off «скорость доступа~--- степень сжатия».
\end{enumerate}

Решение перечисленных задач составляет содержание последующих глав: в главе~\ref{architecture} рассматривается общая архитектура и принимаемые проектные решения, в главе~\ref{implementation} описываются детали реализации ключевых компонентов, а в главе~\ref{experiments} приводятся результаты экспериментов.
